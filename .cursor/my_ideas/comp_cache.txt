Cache Component (comp [cache])
A transparent cache sitting between one or more masters (CPU, DMA, future devices) and a backing memory (comp [mem], another cache, or a future comp [mmap]).
The cache implements the same memory interface as comp [mem], therefore existing components do not need to know whether they are connected to RAM or to a cache.
Typical uses:
• CPU L1 cache
• DMA copy cache
• Shared L2 cache
• Teaching cache hits, misses and cache coherency
• Building multi-level memory hierarchies
For memory devices see mem.md. For DMA see dma.md. For CPU integration see cpu.md.

───

Basic example
logts
comp [mem] .ram:
  depth: 8
  length: 256
  on: 1
:

comp [cache] .l1:
  mem = .ram

  lines: 16
  lineSize: 4

  on: 1
:

comp [cpu] .cpu:
  ram = .l1
:

The CPU accesses .l1.
The cache automatically loads and writes memory through .ram.
The CPU does not know that a cache exists.

Memory path:
CPU
 ↓
L1 Cache
 ↓
L2 Cache
 ↓
RAM

No CPU changes are required.

───

DMA cache
logts
comp [mem] .rom:
...

comp [mem] .ram:
...

comp [cache] .cache:
  mem = .ram
:

comp [dma] .dma:
  mems: .rom .cache
:

DMA writes into the cache.
Dirty lines are later written back to RAM according to the selected write policy.

───

Shared cache
logts
CPU
  ↓
Shared Cache
  ↓
RAM

DMA
  ↓

Both CPU and DMA access the same cache.
This configuration naturally maintains coherency because both masters observe the same cached data.

───

Attributes

Attribute
Description

mem =
Backing memory or another cache. Required.

lines:
Number of cache lines.

lineSize:
Number of words stored by each cache line.

replacement:
lru, fifo, or random. Default lru.

writePolicy:
writeBack (default) or writeThrough.

writeAllocate:
1 (default) or 0 (noWriteAllocate).

on:
Component enable mode.



───

Replacement policies
LRU
Least Recently Used.
The oldest unused line is replaced.
Best general-purpose algorithm.

───

FIFO
First line inserted is evicted first.
Simple and deterministic.

───

RANDOM
A random line is replaced.
Useful for experimentation and teaching.

───

Write policies
writeBack
Writes modify only the cache.
Modified lines become dirty.
Dirty lines are written to memory only when evicted or flushed.
Advantages
• fewer RAM writes
• faster

───

writeThrough
Every cache write immediately updates backing memory.
Advantages
• always coherent with RAM
• simpler behaviour
Disadvantages
• more memory traffic

───

Write allocation
writeAllocate = 1
Write miss first loads the cache line.
Then the write modifies the cache.
Most modern CPUs use this mode.

───

writeAllocate = 0
Write miss bypasses the cache.
The data goes directly to memory.
Useful for DMA-style sequential transfers.

───

Pins

Pin
Description

flush
Write every dirty line back to memory.

invalidate
Invalidate one cache line.

invalidateAll
Invalidate every cache line.

line
Cache line used with invalidate or inspection.

adr
Memory address used for inspection.

set
Execute requested operation.



───

Pouts

Pout
Description

hits
Total cache hits.

misses
Total cache misses.

hitRate
Hit percentage.

evictions
Number of replaced lines.

dirtyEvictions
Number of dirty write-backs.

busy
Cache currently performing an internal operation.

valid
Selected cache line contains valid data.

dirty
Selected cache line has been modified.

tag

data
Entire selected cache line.



───

Flush example
logts
.cache:{
    flush = 1
    set = 1
}

All dirty cache lines are written to backing memory.

───

Invalidate one line
logts
.cache:{
    line = 5
    invalidate = 1
    set = 1
}

Cache line 5 becomes invalid.
Next access generates a cache miss.

───

Invalidate all
logts
.cache:{
    invalidateAll = 1
    set = 1
}

Every cache line becomes invalid.
Useful after DMA transfers or software reset.

───

Inspecting cache contents
logts
.cache:{
    line = 2
    set = 1
}

show(.cache:valid)
show(.cache:dirty)
show(.cache:tag)
show(.cache:data)

Useful for debugging and teaching.

───

CPU + cache + DMA
logts
comp [mem] .ram:
...

comp [cache] .cache:
    mem = .ram
:

comp [cpu] .cpu:
    ram = .cache
:

comp [dma] .dma:
    mems: .rom .cache
:

CPU and DMA both access the same cache.
This naturally avoids coherency problems because every access goes through one cache.

logts

 ↓
Cache
 ↓
RAM

DMA
 ↓

This is the classic desktop architecture.
DMA bypasses the cache.
Software typically invalidates affected cache lines after DMA finishes.

───

Cache coherency
When every master accesses the same cache, coherency is automatic.
If multiple independent caches exist, software or future hardware coherence mechanisms must invalidate or update affected cache lines after writes.
Future versions may introduce optional cache snooping or coherence protocols.
